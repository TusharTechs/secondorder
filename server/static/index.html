Agent memory stores what is true, or what I know. SecondOrder also stores what you know, and what you think I know. It gives multi-agent systems theory of mind, with one FalkorDB graph per mind.

Graph layout: many graphs, one FalkorDB

so:<sid>:world           ground truth + who witnessed what
  (:Agent)-[:WITNESSED]->(:Event)-[:ABOUT]->(:Entity)-[:IS]->(:Value)
  (:Agent)-[:IN|EXITED {t,chapter}]->(:Room)   (:Agent)-[:TOLD]->(:Agent)

so:<sid>:mind:<agent>    everything that agent believes
  (:Perspective {chain:'Maya'})
  (:Perspective {chain:'Shipping>Maya'})  what Shipping thinks Maya believes
  (child)-[:INHERITS]->(parent)
  (:Perspective)-[:BELIEVES {entity, active, t, via, src}]->(:Value)

A perspective stores only where it diverges from its parent. When an event happens, every perspective whose members all witnessed it is updated. Children that did not witness it are first frozen at their old value (copy-on-write per belief edge). Reading a 4th-order belief is one Cypher walk up the INHERITS tree.

Why one graph per agent

Each agent connects as its own FalkorDB ACL user allowed only GRAPH.RO_QUERY on so:*:mind:<agent>. It can ask what it believes and what it thinks others believe, but it cannot read the world graph or another agent's mind. That is theory of mind, not omniscience. Supervisors and the planner use the world graph.

Resolve a nested belief (Cypher)

MATCH (p:Perspective) WHERE p.chain IN $prefixes
WITH p ORDER BY p.depth DESC LIMIT 1
MATCH path = (p)-[:INHERITS*0..6]->(q:Perspective)
      -[b:BELIEVES {entity: $entity, active: true}]->(v:Value)
RETURN v.name, b.via, b.t, b.src, q.chain, length(path)
ORDER BY length(path) ASC LIMIT 1
